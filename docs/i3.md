# i3 and picom rules

The focus changes on a click and not when the pointer passes over a window. The popups, the history and the launcher close when they
lose the focus, so with the focus following the pointer they closed as soon as it left them:

```
focus_follows_mouse no
```

The toasts are a floating window, and i3 has to know it:

```
for_window [title="^nshell-toast$"] floating enable, border none, sticky enable
no_focus [title="^nshell-toast$"]
```

The history center is a window of its own, in the same corner. It takes the focus, to close with Escape:

```
for_window [title="^nshell-center$"] floating enable, border none, sticky enable
```

The menu of an icon of the tray is a window under the icon, which closes when it loses the focus:

```
for_window [title="^nshell-menu$"] floating enable, border none, sticky enable
```

The card of the polkit agent is a window of its own in the middle of the screen. It takes the focus, so that Escape cancels it
and the password can be typed:

```
for_window [title="^polkit$"] floating enable, border none, move position center
```

The launcher is a card in the middle of the screen. It takes the focus, so that the search field gets the keys:

```
for_window [title="^nshell-launcher$"] floating enable, border none, move position center
```

The menu of the session is a card in the middle of the screen too. The right button of the logo opens it, and a key can, as `nshell session` toggles
it. Log out is `i3-msg exit` by default, so think before you bind it where a stray press ends the session:

```
for_window [title="^nshell-session$"] floating enable, border none, move position center
bindsym $mod+Shift+e exec --no-startup-id nshell session
```

The volume on the screen is a window at the bottom that never takes the focus. The shell shows it when the volume of
the default output changes, so the keys only have to change the volume, and `wpctl` does it:

```
for_window [title="^nshell-osd$"] floating enable, border none, sticky enable
no_focus [title="^nshell-osd$"]
bindsym XF86AudioRaiseVolume exec --no-startup-id wpctl set-volume -l 1 @DEFAULT_AUDIO_SINK@ 5%+
bindsym XF86AudioLowerVolume exec --no-startup-id wpctl set-volume -l 1 @DEFAULT_AUDIO_SINK@ 5%-
bindsym XF86AudioMute exec --no-startup-id wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle
```

Without the rule the window opens as a tile, as big as the screen.

The tabs of the tabbed containers are shown by the shell, in the bar, after the number of their workspace, and i3 draws nothing for
them: the colors of the tabs are transparent, with no title and no icon. The room that i3 keeps above a tabbed container is a font
height and 4 px, which stays as an empty band; the patch of the user keeps 2 points. The module writes this as `i3-<mode>.conf`; by hand:

```
client.focused          #00000000 #00000000 #00000000 #00000000 #00000000
client.focused_inactive #00000000 #00000000 #00000000 #00000000 #00000000
client.unfocused        #00000000 #00000000 #00000000 #00000000 #00000000
client.urgent           #00000000 #00000000 #00000000 #00000000 #00000000
client.placeholder      #00000000 #00000000 #00000000 #00000000 #00000000
client.background       #00000000
for_window [all] title_format " "
for_window [all] title_window_icon off
bindsym $mod+s exec --no-startup-id nshell tabs list
```

The last line opens the list of the windows of the tabbed container that has the focus, under its chevron in the bar.

picom draws a shadow behind a transparent window and rounds its corners, which shows as a grey box around the cards:

```
{ match = "name = 'nshell-toast' || name = 'nshell-center' || name = 'nshell-menu' || name = 'polkit' || name = 'nshell-launcher' || name = 'nshell-session' || name = 'nshell-osd'"; shadow = false; corner-radius = 0; }
```

## The patch of i3 (`nix/apps/i3.patch`)

The shell shows the tabs of i3 in its bar, and i3 draws nothing for them, but it still reserves room for them, and it has two habits that
do not suit this: it keeps the windows of the tabs that are not in front mapped under the one that is, and it gives no gap between the
windows of a split inside tabs. The patch changes three things, in `src/render.c` and `src/gaps.c`:

- the room above a tabbed container is 2 points, not the height of the font and 4 px;
- the windows of a split inside tabs get the gap between them, and the container of the tabs gives the one at the edges;
- the tabs that are not in front are not mapped when the one in front is a split of windows, or one of them is seen through the gap.

The flake has it as an overlay, and applies it to the i3 of the pkgs that it is used with:

```nix
nixpkgs.overlays = [ inputs.nix-quickshell.overlays.i3 ];
```

and the i3 of the pinned nixpkgs, `nix build .#i3`, tells if the patch still applies. It was made for i3 4.24 and builds on 4.25.1. The tests of i3
are off in the overlay: they drag a tab with the pointer at the places of its default height, which the patch changes. The build stops
where the source of i3 has changed, which tells that the patch has to be looked at.

Without the patch the shell works, with a band of font height and 4 px above the tabbed containers and the hidden tab seen through the gaps of a split.
